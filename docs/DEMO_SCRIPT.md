## 第 1 幕 · 知识库概览

**操作**
```powershell
python demo.py --scene 1
```

**预期输出**：教材信息、12 章的块数与页码覆盖表。

**讲解词**

> 我们选的教材是《计算机体系结构基础》，430 页、12 章。
> Phase 1 把它变成了右边这张表——每一章都被切成了若干知识块，
> 并且记录了每块对应的**教材页码**。
>
> 这个页码信息非常关键，它让后面「每个回答都附页码引用」成为可能。
> 整本教材一共 277 个块，平均每块 1082 个 token，
> 其中 97.5% 落在作业要求的 800~1200 区间内。

**可能的追问**

| 追问 | 回答 |
|---|---|
| 章节边界怎么定的？ | 读 PDF 自带书签，不是正则匹配。这本教材由 LaTeX 生成，有 210 条书签，层级是「部分/章/节/小节」，直接取 level≤2 就是章，零误判。 |
| 为什么是 277 块？ | 按 1000 token 目标、800~1200 上下限、块间 180 字符重叠切出来的。最大化语义完整性的同时卡住粒度。 |
| 块之间重叠不会重复吗？ | 会刻意保留 180 字符重叠，防止答案正好被切在块边界上导致检索不到。这是有意为之。 |

## 第 2 幕 · 检索演示（R1）

**操作**
```powershell
python demo.py --scene 2
```

**预期输出**：3 个问题，每个返回 Top-3 片段，附带章节名、页码、耗时。

**讲解词**

> RAG 的第一步永远是**检索**，这也是作业 R1 的要求：
> 回答任何课程问题前必须先检索知识库。
>
> 我现场问三个问题，大家看返回的片段——
> 每个片段都标了它来自哪一章、哪一页。
> 比如问「TLB 地址翻译」，检索到的是第 3 章「特权指令系统」的存储管理小节，
> 页码 p.104 到 p.109。**检索是准的**。
>
> 注意耗时只有 7 到 13 毫秒，因为我们用的是 SQLite 内置的 FTS5 全文索引，
> 不需要 GPU、不需要向量数据库。

**可能的追问**

| 追问 | 回答 |
|---|---|
| 中文没有空格，全文检索怎么做？ | 这是关键难点。FTS5 默认的 `unicode61` 分词器会把整句中文当成一个 token，中文查询全部 0 命中。我们换成 `trigram` 分词器，按 3 字符滑窗切，中文子串就能匹配了。 |
| 为什么不用向量检索？ | 对比过。向量检索要引 embedding 模型和向量库，依赖重；而且对这个场景——中文教材、术语精确——BM25 的确定性和可解释性更好，也便于我们逐条验证 R1~R6。 |
| 检索不准怎么办？ | 我们做了两层优化：一是同义词扩展，比如用户说「映象」而教材用「相联」；二是二次排序，先召回 40 个候选再做精排。 |

## 第 3 幕 · 页码引用可追溯（R3）

**操作**
```powershell
python demo.py --scene 3
```

**预期输出**：检索片段的真实页码集合，以及每处引用与真实页码的比对结果。

**讲解词**

> 作业 R3 要求每个事实性陈述都要附页码引用，格式是【教材 p.XX】。
>
> 但这里有个陷阱：**如果只是让大模型自己写页码，它是会编的**。
> 所以我们做了个可验证的设计——页码不是模型生成的，
> 而是直接来自检索片段的元数据字段。
>
> 大家看屏幕：左边是检索片段实际覆盖的页码，
> 右边是生成的引用，每一个都能对上。**引用无法编造**。

**可能的追问**

| 追问 | 回答 |
|---|---|
| 那怎么证明不是碰巧？ | 测试脚本里有专门的核查：提取回答中所有引用，逐个检查页码是否真的落在检索片段的 page_start~page_end 范围内。不在范围内就判定为编造，直接 FAIL。 |
| 万一模型改了页码呢？ | 代码层做了约束——引用串由检索工具直接生成好放进片段里，模型是「抄」而不是「算」。 |

## 第 4 幕 · 诚实性（R2 / R5）★ 重点

**操作**
```powershell
python demo.py --scene 4
```

**预期输出**：两个问题的回答都是「教材未找到相关内容」。

**讲解词**

> 这一幕是我认为**整个系统最重要的地方**。
>
> 我问两个教材里根本没有的问题：
> 一个是量子计算的，一个是让我写 Java 代码的。
>
> 注意看第二行：FTS 原始命中 **5 条**。
> 也就是说全文检索**确实返回了结果**——因为它抓到了「指令」「程序」这些词。
> 如果我们直接把检索结果丢给大模型，它就会一本正经地拿这些无关内容编答案。
>
> 所以我们加了一个**相关性闸门**：计算问题里的实义关键词有多少能在
> 命中的片段里找到，覆盖率低于 0.34 就判定为「教材没讲」。
> 结果就是大家看到的——老实回答「教材未找到相关内容」。
>
> **这一点其实是我们在测试中发现的问题**。最初版本没有这道闸门，
> 问 Java 冒泡排序它也会答，这违反了 R2 和 R5。加闸门之后通过率从 80% 提到 100%。

**可能的追问**

| 追问 | 回答 |
|---|---|
| 阈值 0.34 怎么来的？ | 实验调出来的。太低会放过无关内容，太高会把正常问题也拦掉。我们用测试用例反复调，兼顾两个方向。 |
| 如果问题一半在教材里、一半不在？ | 提示词第 14 条专门规定：必须分别说明哪部分有依据、哪部分未覆盖，不能把没依据的部分也写成肯定结论。 |

## 第 5 幕 · R1~R6 合规性总览

**操作**
```powershell
python demo.py --scene 5
```

或现场跑完整测试：
```powershell
python test/run_smoke_test.py
```

**预期输出**：R1~R6 六行，每行 5/5 PASS，总计 30/30。

**讲解词**

> 最后是合规性总览。作业要求的 R1 到 R6 六条约束，
> 我们用 5 个测试用例、共 30 项**程序自动核查**，全部通过。
>
> 强调一下「自动核查」——这不是我们人工看一眼说"没问题"，
> 而是写了判定逻辑：比如 R6「不能复制大段原文」，
> 脚本会拿检索片段和回答做比对，统计最长连续原文复制了多少句，超过 3 句就 FAIL。
>
> 而且测试用例专门覆盖了三类场景：正常问题 3 个、
> 教材未覆盖 1 个、超出教材范围 1 个。**后两类才是真正考验系统的地方**。

**可能的追问**

| 追问 | 回答 |
|---|---|
| R1「先检索」怎么自动验证？ | 读执行日志里的 `retrieval_called` 标志，并检查检索发生在回答之前。 |
| 这些测试用例是你们挑的好答的题吗？ | 不是。我们故意放了两个「陷阱题」——量子计算和 Java 代码，就是为了验证系统在无依据时会不会编造。而且这两题最初确实没通过，是我们改了代码才过的。 |

## 第 6 幕 · 总结

**操作**：自动播放，无需干预。

**讲解词**

> 总结一下。这个系统的核心不是「能回答问题」，
> 而是作业说的那句话——**约束行为、开放实现**。
>
> 六条约束分别对应六个机制：
> R1 靠提示词加代码双重强制；
> R2 靠相关性闸门；
> R3 靠页码从检索元数据直接来；
> R4 靠提示词规定术语格式；
> R5 靠固定话术加闸门拦截；
> R6 靠每片段限取 2 句。
>
> 我们还额外做了一件事：**把整个流程写成了一条命令就能跑的演示脚本**，
> 也就是大家刚才看到的这些。代码和文档都在 GitHub 上，欢迎大家来看。

## 附：演示后可能被问到的技术细节

**Q：为什么选方案 C 而不是老师参考的方案 A？**

> 作业明确说「选择非参考路径且实现完整者，技术选型项可获满分」。
> 方案 A 是 DSH 框架 + 插件，我们选 C 是从零搭建、直接调 LLM API。
> 好处是每个环节都自己实现，理解更深，而且整个链路是可复现的。
> 另外我们也**额外提供了 DSH 插件的实现**，所以并不排斥方案 A 的生态。

**Q：不用 API Key 也能演示？**

> 可以。演示用的是 `--offline` 离线模式，不调用任何大模型，
> 用模板加检索结果生成抽取式回答。
> 这反而是个优点——**结果完全确定、可复现**，特别适合做合规性验证。
> 接大模型只是换个 `--api` 参数。

**Q：这个系统和直接问 ChatGPT 有什么区别？**

> 三个区别：一是**只答教材内容**，教材没有的就说没有；
> 二是**每句话都有页码**，可以翻书核对；
> 三是**不会大段复制原文**，规避版权问题。
> 本质上，我们是用工程手段把「幻觉」和「版权」这两个风险按住了。

**Q：最大的难点是什么？**

> 中文检索。一开始用 FTS5 默认分词器，中文查询全部 0 命中，
> 排查后换成 trigram 才解决。
> 另一个难点是分块——早期版本产生了很多 600 token 的半满块，
> 我们写了诊断脚本复刻主循环、打印每次断块的原因和大小，
> 才发现是「超限就二分」的逻辑把 1201 切成了两个 600。改成容忍轻微超限就好了。
