# 课堂远程演示指南

> 场景：教室电脑远程连接自己的电脑，在自己电脑上实时运行系统演示
> 环境：Windows，1920×1080，已装 Chrome / Edge
> 本文所有命令与耗时均经过实机验证

---

## 一、远程演示的优势与风险

**优势**——环境完全可控：

- 知识库、依赖、字体都是你熟悉的，不会出现「教室电脑没装 Python」
- 可以预先测试，风险远低于现场配置
- 学生看到的是你真实的开发环境

**风险**——远程连接特有的两个坑：

| 风险 | 后果 | 对策 |
|---|---|---|
| 网络延迟 | 逐行输出卡顿、画面撕裂 | 关掉 `--slow` 或调小延迟 |
| 分辨率/缩放变化 | 字号变小、排版折行 | 演示前调整好字号 |

> **重要**：远程时分辨率或缩放会变，可能导致终端里的 78 字符排版折行。
> **演示前务必最大化窗口**，并实测一次 `python demo.py --fast` 看排版。

## 二、能演示什么（功能清单）

以下 7 项**全部实测可用**：

| # | 功能 | 命令 | 时长 | 说服力 |
|---|---|---|---|---|
| 1 | 知识库概览（12 章 277 块） | `demo.py --scene 1` | 15 秒 | ★★★ |
| 2 | 检索演示（毫秒级返回） | `demo.py --scene 2` | 30 秒 | ★★★ |
| 3 | 页码引用可追溯 | `demo.py --scene 3` | 20 秒 | ★★★★ |
| 4 | **诚实性验证（未覆盖即说明）** | `demo.py --scene 4` | 30 秒 | **★★★★★** |

**核心是 4 和 6**：一个证明系统不乱编，一个能让学生参与。

## 三、推荐的演示顺序（10 分钟）

### 第 0 步 · 课前提早 5 分钟做

```powershell
cd "D:\deepseek工作区\arch-rag-kb"
python scripts\precheck.py
```

看到「自检通过，可以开始演示」才放心。

> 远程连接前**先在本机跑一次**，确认没问题再接教室电脑。

### 第 1 步 · 开场（30 秒）

展示项目目录：

```powershell
dir
```

> 讲：「这是一个完整的工程，从建库、检索、问答到测试报告都在里面。」

### 第 2 步 · 知识库概览（1 分钟）

```powershell
python demo.py --scene 1
```

输出 12 章的块数与页码表。

> 讲：「教材 430 页被切成 277 块，每块都记录了对应页码。
> 这个页码信息是后面所有引用的来源。」

### 第 3 步 · 检索演示（1 分钟）

```powershell
python demo.py --scene 2
```

3 个问题，每个返回 Top-3 片段，带页码和章节。

> 讲：「注意耗时——7 到 13 毫秒。因为用的是 SQLite 内置全文索引，
> 不需要 GPU，也不需要向量数据库。」

### 第 4 步 · 页码引用（1 分钟）

```powershell
python demo.py --scene 3
```

屏幕上会把引用与真实页码逐条比对。

> 讲：「页码不是大模型编的，是从检索结果里直接取出来的。
> 所以每句话都能翻书核对。」

### 第 5 步 · 诚实性验证 ★重点（2 分钟）

```powershell
python demo.py --scene 4
```

**这一屏是全场最有说服力的**，你要停下来重点讲：

```
  提问：请帮我写一份 Java 的冒泡排序代码。
    FTS 原始命中：5 条          ← 注意
    相关性闸门  ：拦截

    教材未找到相关内容。
  [OK] 如实回答「教材未找到相关内容」，未编造 [符合 R5]
```

> 讲：「看这里：全文检索**确实命中了 5 条**——因为它抓到了『指令』『程序』
> 这些词。但这些都是无关内容。
>
> 如果把这种结果直接丢给大模型，它就会拿着无关材料，
> 一本正经地编出一个答案。这是 RAG 最常见的翻车方式。
>
> 所以我们加了一道**相关性闸门**，判断检索结果到底相不相关。
> 不相关就老实说『教材没找到』。」

### 第 6 步 · 现场互动问答（3 分钟）

这是最能调动气氛的环节。让学生提问，你当场输入：


**建议引导学生从教材目录里挑问题**（`data/chapters.json` 有 12 章标题），命中率最高。

**已验证可答的问题**（实测，可以直接用）：

| 多核处理器怎么保证缓存一致性 | 多核处理结构 p.318-319 |

| 程序局部性是什么意思 | 引言 p.58 |

### 第 7 步 · 合规性总览（1 分钟）

## 四、远程连接的注意事项

### 1. 终端字号

远程后屏幕分辨率/缩放可能变化。演示前确认：

- 最大化终端窗口
- 字号 ≥16pt（Windows Terminal：`Ctrl + 加号`）
- 实测一行能否放下 78 个字符（看输出有没有折行错乱）

### 2. `--slow` 延迟要调小

本机 0.1 秒完成的操作，经过远程可能变慢。**建议**：

- 网络好：`python demo.py --slow 0.15`
- 网络一般：`python demo.py --slow 0.08`
- 网络卡：**不用 `--slow`**，直接 `python demo.py`

> 逐行延迟 + 网络延迟会叠加，显得卡顿。宁可快一点，让学生看结果。

### 3. 提前测试远程环境

**务必在演示前，用同样的远程方式跑一遍** `python demo.py --fast`。
只有这样才能发现远程特有问题（字体缺失、显示折行、延迟卡顿）。

### 4. 保持连接稳定

- 关闭本机的大流量程序（下载、同步盘）
- 关闭系统自动更新提醒
- 笔记本插电源，别用省电模式（会导致降频卡顿）

## 五、现场问题处理

### 输出刷太快 / 看不清

```powershell
python demo.py --slow 0.2
```

### 显示 `[exit code: 1]` 但其实成功了

**这是 PowerShell 管道截断造成的假警报。**

如果你用过 `| Select-Object -First 10` 之类的管道，PowerShell 会返回 exit code 1，
但程序本身成功了。

**课堂上直接跑命令，别加管道**，就不会有这个问题。

### 中文乱码

```powershell
chcp 65001
$env:PYTHONIOENCODING = "utf-8"
```

`demo.py` 已内置 UTF-8，通常不会乱码。

### 学生问到教材没覆盖的

这是**好事**，正好演示 R5。直接问：

```powershell
python agents/arch_tutor_agent.py "学生的问题" --offline
```

系统会回答「教材未找到相关内容」，你可以顺势讲诚实性设计。

> ⚠️ **一个已知边界**：问「量子计算机怎么做」时，系统会放行并返回
> 教材 p.374 的片段。原因是教材在**测试程序集列表**里出现过
> 「462.libquantum」这个条目名，但不是讲解量子计算。
>
> 万一被问到，可以坦诚说明：「这是闸门的边界情况——教材只是提到过
> 这个词，并没有讲解。我们的闸门按关键词覆盖率判定，
> 对这种『只提及不讲解』的情况还不够精细，是后续改进方向。」
>
> 坦诚比硬撑好，这也正好呼应 R5 的原则。

### 网络断了 / 远程失败

**备用方案**：

1. 直接放 `deliverables\Arch-Tutor_系统展示.pptx`（18 页，数据全来自真实运行）
2. 讲设计思路 + PPT 里的截图数据，照样能讲完整场

## 七、讲解词速记（最关键三句）

**讲定位**
> 「这个系统只依据这一本教材回答问题，每句话都能翻书核对，
> 教材没讲就明说没讲。」

**讲第 4 幕（最有说服力）**
> 「FTS 明明命中了 5 条，但系统还是说『没找到』——因为命中的都是无关内容。
> 这正是 RAG 最容易翻车的地方，我们用相关性闸门挡住了。」

**讲总结**
> 「这个系统的核心不是『能回答』，而是『守规矩』。
> 用工程手段把幻觉和版权两个风险按住了。」
